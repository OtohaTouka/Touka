# ADR-0307：換家交接工作與子對話回報

- 狀態：✅ 後端已實作（路線圖 3d PR 2b）；畫面在 PR 3。一頁計畫由維護者核准（2026-11-07）。

## 背景

ADR-0306 記下誰換到誰、舊家唯讀、交接完成前不能刪，交接工作本身留到這裡。沒有這一步，舊家原文會一直帶在主線裡、舊家也一直不能刪。

## 決定

1. **觸發只在禁令 28 的兩處**，都是背景排程，不拉長回覆或心跳：
   - 聊天一輪存好之後（`dispatcher._maybe_trim_after_chat`，網頁與 IDE；無痕不走這裡）。綁靈魂的對話都排：家、子對話、舊家。舊前綴的寫法算同一個靈魂（家也一樣）。沒有靈魂的對話不排。
   - 心跳結束時（`finally`，靈魂的心跳、至少完成一個脈衝、開跑之後沒被重置或刪除）。排的時候這次心跳已經拿掉登記。
   - 剪裁失敗也排：交接和剪裁是兩件事。
2. **每個靈魂最多一個維護在跑**（`home_handover.schedule`）：跑的時候再來的只留記號，跑完再檢查一次。整次拿靈魂鎖（`soul_locks.soul_lock`，和前情合併共用）；鎖的順序是靈魂鎖在最外層 → 剪裁的對話鎖 → 存檔的對話鎖 → SQLite 交易，模型呼叫都在交易外。重置或刪除中不做，每個寫入都再查一次；歸檔與回報的模型呼叫之前也查，重置開始後不再花錢。
3. **交接依紀錄編號一筆筆做**。
   - 新家還沒開始用的紀錄不做（改回去要能當沒換過）。沒有新家（取消家）的、已開始用的、做到一半的才做。
   - 舊家還有回覆或心跳在跑、或收尾保存還在等（聊天的收尾等待現在舊家也等；SNS 家模式的回覆在 `reply_in_flight` 登記），這次到此為止、等下一次觸發；舊家已經又是現任家時不等。
   - 認領之後重讀一次舊家：判斷要不要等的那次讀取和認領之間還可能有一筆保存，認領之後存檔閘才關上，這時讀到的才是最終內容。
   - 認領和之後每一步的交易都核對狀態、步驟、新家、開始用沒變（設家不拿靈魂鎖，會改寫還沒開始的紀錄）。
4. **一筆紀錄的步驟**（`step` 記做到哪，中途停下從下一步接著做；舊對話庫只新增、段落有唯一索引，重做不重複）：
   1. 舊家整棵樹進舊對話庫：所有節點帶 `parentId`，插話併進內容，工具步驟留在附註。舊家已不存在時寫一行「原文已刪除」，這一筆完成。
   2. 退任摘要（輸出上限 2,000）。舊家已經又是現任家時標「待補」；前情摘要關閉時寫一行來源註記；摘要失敗不算交接失敗，放回佇列隔 1 小時再試（次數記在記憶體），第三次還是失敗才寫來源註記：幾個小時內的故障不會永遠失去這段摘要，故障更久（連續兩小時以上，且期間有維護觸發）時交接仍會結束，不會讓舊家一直不能刪。
   3. 子對話回報（一次維護總共最多 5 段，最多同時 3 段）。
   4. 一行換家標記。
   5. 完成。
   - **只記新家的紀錄**只寫換家標記，不讀它記的舊家（可能已刪或已是普通對話）；同一筆交接指向同一段的只寫一行；第 0 筆（沒有前任）一筆一行。換家標記的時間是這次換家發生的時候（改指新家時跟著改）。
5. **失敗**：累計三次標成失敗、寫一行註記、繼續做後面的；沒滿三次回到待交接、步驟保留。失敗的每次啟動後第一次觸發、或滿 24 小時再試。失敗紀錄在 `/v1/stats` 的 `failed_handovers` 看得到（只列 `can_access_session` 放行的靈魂），舊家在這段期間照舊唯讀、原文照舊帶在主線。後來成功時，那行失敗註記失效。
6. **補寫退任摘要**：佇列做完之後，標「待補」的舊家不是現任家、也沒有別筆還沒完成的紀錄時補寫；補寫前再歸檔一次（補上歸檔之後新增的節點）。補寫沒有重試，摘要失敗就寫來源註記。
7. **子對話回報**（`child_report`，輸出上限 800）：候選是綁這個靈魂、不是家、不是舊家、不是頻道的對話，目前節點和回報位置不同，而且沒有回覆或心跳在跑。
   - 時機：交接時寫前幾段；另外每 30 分鐘最多檢查一次 6 小時沒動、有新內容的（候選要解析每段子對話的內容，不必每一輪都做），一次最多 5 段。
   - 位置失效（範圍版本 0）跳過；沒有位置的只有範圍版本 1 的對話算全部新內容；換靈魂時同一個交易移位置、記新靈魂：換之前的內容不報給新靈魂、換之後的照報。兩條路都移：畫面在空對話換靈魂的存檔（`save_ui_session`，移到當下），以及有內容的對話送出時的准入（`admit_ui_stream`，移到這一輪使用者那則之前，第一句算新內容）。升級前換過的舊資料在維護時移。
   - 位置在別的分支（重新生成、切分支）：只算兩條路分岔之後的；完全沒有共同祖先才整條都算。位置那則已被刪（刪了最後一輪）：只算位置移動之後才有的（節點時間可能來自使用者裝置，寧可少報）。
   - 段落和位置同一個交易；交易裡再確認對話還在、還綁同一個靈魂、位置沒失效。沒有對話內容的只移位置、不花模型；同一個節點已經寫過回報的（切分支又切回來）也是。
   - 前情摘要關閉時不寫。摘要失敗時位置不動，分兩種：請求根本沒送出（Anthropic、Gemini、Responses 三條路線沒金鑰，超預算，模型不可用）這個靈魂冷卻 6 小時（記在記憶體），恢復後照常補寫；送出去卻失敗（拒答、安全攔截、截斷、空回應、逾時、上游錯誤）只影響這一段，6 小時後再試，三次就放棄：寫一行來源註記、位置移到當下，不會整段重送下去。失敗過、還在等待的段落不佔名額。
   - 使用者刪掉子對話時，它還沒併進合併段的回報在同一個交易失效。
8. **SNS（維護者 2026-11-08）**：SNS 獨立頻道、SNS 家模式、SNS 群聊的請求不帶子對話回報；家原文、剪裁摘要、舊家尾端照舊。吃進回報的合併段來源欄記 `#child-reports`，SNS 請求連它一起排除（否則回報併進合併段之後就漏出去）。剪裁摘要員的「前情最後一段」背景也不給有回報內容的段落（否則回報可能被寫進 `home_trim`，而 `home_trim` 會給 SNS）。群聊白名單裡別的擁有者的靈魂被外人 @ 那題不在這裡，列在路線圖候選。
9. **修訂 ADR-0305 的合併規則**：
   - 退任摘要可以合併；否則比合併段舊的那幾段會被折掉、永遠看不到。一行來源註記照舊不合併。現任家自己的退任摘要不顯示，也不會被合併。
   - 同一來源被取代的舊版退任摘要一起標成已合併，不會重新出現。
   - 比合併段新的段落已達 `PRELUDE_MAX_SEGMENTS - 1` 時不合併（合併段排在最前面，下一段寫進來就被折掉）。
   - 維護寫了新段落之後，在靈魂鎖外試一次合併（合併自己拿靈魂鎖）。
10. **範圍版本**：失效的紀錄不處理。交接不看對話的 `session_scope_version`（2026-10-17 以前的家永遠是 0）。

## 影響

- 換家之後多幾次摘要模型呼叫（退任摘要一次、回報每段一次），都走前情摘要的設定與模型，關掉 `prelude_summary_enabled` 時不呼叫。失敗時有上限：退任摘要每筆最多三次（1 小時一次），回報每段送出後失敗最多三次（6 小時一次）；請求根本沒送出時不花錢。
- 摘要實際的輸出上限比告訴模型的多四分之一（`dialogue_summarizer`）：寫超過一點時不會因為截斷整份作廢。
- 交接完成後舊家原文不再帶在主線，舊家可以刪。
- `/v1/stats` 多一個欄位（dict 折入，不動 openapi）。

## 已知限制

- **交接開始後在舊家送出**：畫面送出前會先存使用者那則，被存檔閘擋下（1223）時改跳舊家提示、內容退回存檔的樣子、文字放回輸入框，不留等人核對的保存失敗（`SessionListProvider.updateSession`、`StreamRegistryProvider.startStream`）；入口擋下之後存回被擋也一樣不算失敗。舊家的唯讀畫面在 PR 3。
- **回任期間被編輯的內容**：重新歸檔時，同一則內容不同的另存成版本（`legacy_store.archive`），不蓋掉之前歸檔的那份；只有下一筆交接或補寫退任摘要時才會重新歸檔，回任期間沒離開就不動。
- **一輪讀出全部還沒交接完的舊家**：ADR-0306 的成本照舊，交接開始之後舊家會陸續離開；交接卡住（失敗）時才會累積，`/v1/stats` 看得到。
- **吃進回報的合併段整段不給 SNS**：裡面的剪裁摘要也一起不帶，寧可少給。
- **冷卻記在記憶體**：回報與退任摘要的失敗次數、等待時間，失敗重試的「啟動後第一次」重啟就清掉；每次重啟重新計數（重啟很頻繁的環境，一直失敗的子對話和退任摘要到不了放棄的次數，重啟後第一次維護就會再試）。
- **回任期間只編輯、沒開一輪就改回去**：那筆回任當沒換過、沒有下一筆交接，這次編輯不重新歸檔；內容還在舊家，舊家被刪就沒了。
- **換靈魂之後切到舊分支**：位置在換靈魂當時的分支上，切到另一支時分岔之後的舊內容會報給新靈魂；換靈魂要能驅動兩邊，同一位擁有者不算外洩。
- **上游長時間失敗**（金鑰失效、額度用完、模型下架、限流、連不上、逾時、5xx 超過十幾個小時）：三次之後子對話會變成一行註記，模型恢復後不補寫；原文還在對話裡。這些失敗多半沒花錢，但目前的原因碼分不出來（連不上和內容太長都可能混在同一個原因碼），寧可少補寫也不要永遠重送；OpenAI 相容路線沒金鑰時會實際送出、收到 401，也算在這裡。
- **退任摘要併進合併段之後**，那段舊家回任時拿不掉（合併段是多段的摘要）；現任家自己的退任摘要不會被合併。
- **刪子對話**：已經併進合併段的回報分不出來，刪不掉。
- **同一個靈魂有好幾位擁有者時**，回報對每一位都一樣：能驅動這個靈魂的人本來就看得到綁它的對話，範圍沒有擴大。
- **摘要走全域的 `summary_model`**：靈魂用本機模型時，子對話內容也會送到摘要模型；沒有每個靈魂的開關，只能全域關 `prelude_summary_enabled`。
- **舊家歸檔保留節點全部欄位**（含工具步驟與附件）：舊家之後可以刪，這份是完整備份；重置不清舊對話庫（ADR-0104）。
- **交接失敗目前只有 `/v1/stats` 和前情裡的一行註記**，畫面提示在 PR 3。
- **閒置回報靠下一次觸發**：靈魂完全沒有活動時，6 小時沒動的子對話要等下一輪或下一次心跳才寫回報。
