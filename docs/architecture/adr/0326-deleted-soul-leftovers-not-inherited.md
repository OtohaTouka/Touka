# ADR-0326：刪掉的靈魂留下的東西不給同名的新靈魂

- 狀態：🔄 部分實作（PR 0 排程頁連線、PR 1 排程、身分設定、統計與用編輯建立；PR 2 SNS 機器人、PR 3 舊對話與封存待做）
- 日期：2026-11-20
- 決策者：維護者（一頁計畫第 2.1 版，總覽板第 96 項回「①甲 ②甲」：照 2.1 版做，四個 PR 依序；統計一起刪、心跳服務連不上時刪除照做而建立不建、自訂模型不處理統計、用編輯建立時名字還在擁有清單或模型清單就當修復，是計畫裡寫明的「我自己定的」）
- 相關：[ADR-0325](0325-mission-board-system-folder.md)（看板與「不屬於任何代理人」的判斷）、[ADR-0230](0230-heartbeat-transaction-and-credential-contracts.md)（排程橋）、[ADR-0303](0303-soul-names-and-who-can-create-souls.md)（靈魂名稱與建立權限）、[ADR-0147](0147-soul-role-type-binding.md)（靈魂與人類帳號不能撞名）、[ADR-0142](0142-soul-crud-repair-and-admin-stepup.md)（刪除範圍）、[ADR-0262](0262-consistent-snapshots-and-soul-delete-memory-check.md)（刪除前的記憶檢查）
- 修訂 ADR-0303（用編輯建立與轉換也擋和人類帳號、自訂模型同名）、修訂 ADR-0142 與 ADR-0262（刪除範圍多了排程、統計，身分設定寫不進去照實回報）、修訂 ADR-0230（排程橋多了系統清理用途）、修訂 ADR-0325（用編輯建立判定為修復時看板不清）

## 背景

靈魂刪掉之後，依它的編號存放的資料有些沒有刪。管理員再建一個同名的新靈魂，新靈魂就接手舊的東西；新靈魂若指給別人擁有，那個人也一起拿到：

- **心跳排程**：喚醒時只看「現在誰擁有這個編號」，舊排程照原本寫的開場提示、權限（可能是 YOLO）、指定模型跑起來。
- **身分設定**（`identity_map.json` 的 `agent_overrides`）：舊版留下、或刪除時沒寫成的角色設定，套在新靈魂上。刪除時寫不進去目前也不會被發現（回傳值沒看）。
- **統計**（`data/stats/<編號>`）：token 用量、今天的自主次數、當機未完成的標記。開了花費上限時，新靈魂可能一出生就被擋。
- 另外，用編輯建立靈魂（只有重新輸入密碼的管理員能用）少了「建立靈魂」有的兩道檢查：和自訂模型同名（共用擁有清單、看板、統計與記憶）、和人類帳號同名（靈魂會被當成那個人）。

SNS 機器人的綁定、舊對話、對話封存與個人空間也會被接手，分別在 PR 2、PR 3 處理（見決定 8）。

## 決定

### 1. 名字的兩種寫法

`utils/agent_spellings.legacy_spellings(編號)` 固定回兩個值：編號逐字、`ToukaSoul`+編號；DebugAgent 沒有前綴寫法，回兩次自己（對話資料庫的 SQL 寫死 `IN (?, ?)`，禁令 24）。對話列的 `_session_agent_candidates` 改用它。只比對逐字：只差大小寫的是另一個代理人（ADR-0303、ADR-0325）。

### 2. 刪除靈魂

- **鎖內**（破壞性操作鎖，ADR-0287）：刪看板之後、刪儲存之前刪統計（`agent_leftovers.remove_stats_on_soul_delete`，經 `resource_manager.remove_dir`）。刪不掉不擋（任何例外都接：這時看板已經刪了，不能讓意料外的例外把刪除變成 500、留下一半），回應的 `skipped` 多一個 `stats`。
- **身分設定**：取消註冊的 `identity_override` 那步改成 `permission_service.remove_agent_overrides(兩種寫法)`，讀不出來或寫不進去就算失敗，整個刪除回 `SOUL_UNREGISTER_INCOMPLETE`（`failed_steps` 含 `identity_override`），再刪一次會補清。
- **鎖外**：放開鎖之後、回應之前刪排程（`remove_schedules_after_delete`）。會連網路的事不在鎖內做。先確認名字仍然不屬於任何代理人（`mission_boards.is_unclaimed`），放開鎖之後同名的新靈魂可能已經建好；整段最多 15 秒（`SCHEDULE_CLEANUP_SECONDS`）。連不上、逾時、結果不明或其他例外都只記警告，刪除照樣成功；這時舊排程沒有擁有者，喚醒時會被拒絕，建立同名靈魂時會再清一次。取消註冊沒做完時（名字還在登記表），這步不刪，再刪一次會補。
- 回 `SOUL_UNREGISTER_INCOMPLETE` 時，`skipped` 的內容也寫進 log。

### 3. 建立靈魂

所有會拒絕的檢查都通過之後、第一個寫入之前（和 ADR-0325 清看板同一個位置），先判斷一次名字屬不屬於任何代理人（`mission_boards.new_board_unclaimed`），結果同時給 `agent_leftovers.clear_for_new_soul` 與 `prepare_new_board`（多一個可選參數 `unclaimed`，不傳時照舊自己判斷，自訂模型不用改）。

不屬於任何代理人時，`clear_for_new_soul` 依序：

1. **排程**：用系統清理的排程橋刪兩種寫法的排程。排程放第一個：它是唯一會連網路、會因為連不上而拒絕的一步，拒絕時看板、身分設定、統計都還沒動。心跳位址設定了卻連不上、結果不明、位址寫錯，就回排程橋的錯誤碼（例如 502 `HEARTBEAT_UPSTREAM_FAILED`），什麼都不建。沒設定心跳位址時不檢查、記警告。
2. **身分設定**：刪兩種寫法的覆寫；讀不出來或寫不進去回 `SYSTEM_ERROR`，不建立。
3. **統計**：刪 `data/stats/<編號>`；刪不掉回 `SYSTEM_ERROR`，不建立。

屬於某個代理人時一律不清（那是它的）。

### 4. 用編輯建立靈魂

- **新資料夾或轉換既有資料夾**：在別名與向量 collection 檢查之後，加上和「建立靈魂」一樣的兩道檢查：人類帳號同名回 422 `VALIDATION_ERROR`、自訂模型同名（有 `config.json` 的）回 409 `MODEL_ALREADY_EXISTS`，什麼都不建、不改。檢查抽成 `_refuse_human_id`、`_refuse_custom_model_id`，「建立靈魂」照原本的先後與錯誤碼呼叫同一組。
- **新資料夾**：除了看板用的判斷，名字還在某人的擁有清單，或模型清單（`models.json`）有這個名字或 `ToukaSoul`+名字（停用、離線的也算；`get_model_ids` 只回開啟且在線的，不能用），算「修復資料夾不見的既有靈魂」：什麼都不清（看板也不清，這是 ADR-0325 的行為改變），也不改擁有者。都沒有才清（同決定 3）。
- **轉換既有資料夾**：不清（是它自己的）。

### 5. 身分設定的寫入鎖

- `permission_service.edit_identity_map(mutate)`：模組層級的 `threading.Lock`（和 `users.json` 的 `_users_file_lock` 同一種；Proxy 只跑單一程序，禁令 37 禁的是 `FileLock`），鎖內從磁碟重讀原始 JSON（不經記憶體快取），交給 `mutate` 改，原子寫回，立刻 `_load_identity_map()`（不等 2 秒一次的熱重載）。`mutate` 回 None 是拒絕、回同一個物件是沒有改動（都不寫）。
- `remove_agent_overrides(編號們)`：只刪 `agent_overrides` 裡這些鍵，其他欄位原樣保留；檔案讀不出來回 False、不寫。
- `/identity` 存檔整段改用它：檔內畫面上看不到的舊覆寫（不能有代理角色的編號）在鎖內從磁碟讀，不讀快取，剛被刪除靈魂清掉的不會寫回；格式不對的略過並記警告。檔案讀不出來時照寫管理員送來的內容（能從畫面修好壞掉的檔）。
- `update_identity` 沒有呼叫端了，刪掉（禁令 46）。

### 6. 排程橋的系統清理

- `HeartbeatScheduleBridge.delete_for_agent(兩種寫法)`：讀一次全部排程 → 帶這次讀到的版本號刪第一筆符合的 → 再讀。版本衝突（`HEARTBEAT_REVISION_CONFLICT`）與找不到（`HEARTBEAT_SCHEDULE_NOT_FOUND`）就重讀；其他錯誤碼原樣往外丟。總次數上限是一開始符合的筆數加 `DELETE_RETRY_ALLOWANCE`（5），用完還有符合的丟 `HEARTBEAT_OUTCOME_UNKNOWN`（刪除回成功、排程卻還在時不會一直轉）。只碰 `can_manage` 放行的編號。
- 系統清理用的橋由 `agent_leftovers._system_bridge()` 建，`can_manage` 一律放行，只給這個模組用；位址、`follow_redirects=False`、10 秒逾時與單送照 ADR-0230。
- 排程的並發由心跳服務的版本號處理（ADR-0230），Proxy 不另外加鎖。

### 7. 自訂模型不處理統計

跟自訂模型聊天時，動作的身分是人類（MonitorLayer 只在目標是靈魂時換身分），token 用量與自主紀錄記在人類名下，自訂模型自己沒有統計。若在刪除自訂模型時刪 `data/stats/<模型名>`，模型名和某個人類帳號同名時反而會刪到那個人的統計。所以自訂模型的刪除與改名不處理統計；測試鎖住「聊自訂模型時身分仍是人類」這個前提。

### 8. 之後的 PR（各自開工前寫細節、另審）

- **PR 2：SNS 機器人**：刪除、建立靈魂時停用綁著這個名字的機器人（`bots.json` 的 `enabled: false`，token 不動），並停掉正在跑的那幾個，不整批重啟其他機器人；`bots.json` 讀改寫加鎖，設定頁存檔共用同一把鎖。
- **PR 3：舊對話、封存、個人空間**：刪掉的靈魂的對話只留給當時聊天的人與管理員；靈魂自己的心跳、SNS 頻道不給新靈魂接著用；刪除時沒刪成的封存與個人空間，建立時不讓新靈魂拿到。

## 沒選的做法

- 排程放在刪除的鎖內刪：會連網路（最多 10 秒逾時）的事放在破壞性操作鎖裡，別的重置、刪除要跟著等。
- 心跳服務連不上時刪除也擋：維護者要能刪掉靈魂；舊排程這時沒有擁有者，喚醒時會被拒絕，建立同名靈魂時會再清。
- 建立時連不上就跳過排程檢查：新靈魂會接手舊排程，正是這次要擋的。
- 另開一個設定項給排程橋：維護者要在 `.env` 多填一項（PR 0 改成接受 `/trigger` 位址）。
- 身分設定用鎖檔（`AsyncFileLock`）：取消註冊與 `/identity` 存檔是同步程式；Proxy 只跑單一程序，程序內鎖就夠。
- 自訂模型刪除時也刪統計：見決定 7。
- 不分大小寫比對名字：只差大小寫的是另一個代理人。

## 已知限制

- 名字還留在登記表（例如刪除時取消註冊沒做完、權限設定的代理人對應在啟動時補進登記表），或 `custom/<名字>` 留著沒有設定檔的資料夾時，算「有人用」，建立時什麼都不清。和看板同一套規則。
- 本機沒設定心跳位址時，排程頁本來就不能用，建立靈魂也不會清舊排程；心跳服務若自己在跑，舊排程照舊會跑。Docker 一定有設定。
- 心跳位址寫成排程橋不接受的形式（例如舊的 `ToukaProxy/.env.example` 註解範例 `/v1/heartbeat/awaken`）時，建立靈魂會回 502、建不起來，要把位址改成心跳服務的根或 `/trigger`。
- 刪除時沒清成的項目，網頁不會顯示（刪除結果目前只顯示成功），伺服器 log 有警告；建立時會再清一次。
- 舊版留下的擁有清單殘留（10 月修好之前刪掉的自訂模型），用編輯建立時會被當成修復。「建立靈魂」會用認領清掉這種殘留。
- 自訂模型平常不會用自己的名字寫記憶、活動紀錄、統計、隔離家目錄，所以自訂模型刪除時不檢查這些。
- 除錯用的「最近一次送出內容」紀錄（滿 5 MB 輪替）、子代理結果暫存（最多 7 天）、除錯快照檔（沒有介面讀回）、MCP 授權（只對同一位擁有者有效）、群聊點名的別名對應、回饋紀錄，照舊。
- 清完之後、建立完成之前，被刪靈魂還沒跑完的那一輪剛好寫進東西：極少數，和看板一樣。
- 升級前已經被同名接手的資料，不會回頭分開。
- 建立靈魂時清排程的結果不明，回的是排程橋原本的 `HEARTBEAT_OUTCOME_UNKNOWN`，訊息說「勿直接重送」；建立靈魂時其實可以再按一次（沒建任何東西，會重讀排程再刪）。訊息照舊，沒有為建立另外寫一句。
