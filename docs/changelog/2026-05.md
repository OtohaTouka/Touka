-   **2026-05-31**: **Skill 系統 Anthropic 標準化與 Dispatch 自動召喚（ADR-0066 + ADR-0067）⭐**
    - **Skill 標準遷移（ADR-0066）**：Touka Skill 系統從單一 `skills.json` 平面格式完全遷移至 [Anthropic Agent Skills 開放標準](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)：每個 skill 為 `config/skills/<id>/` 目錄含 `SKILL.md`（YAML frontmatter + body）+ 選填 `.mcp.json`/`scripts/`/`references/`/`assets/`。新增 `skill_parser.py`（純函式 split/parse/serialize/map_to_contract）。
    - **Progressive Disclosure（三層載入）**：metadata 常駐 → body 觸發 → resources 按需，降低 context 佔用。
    - **MCP 自動掛載**：`mcp_servers` 改由同目錄 `.mcp.json` 的 top-level keys 推導，同一檔案同時服務 Touka 內部自動掛載與外部 AI 安裝 plugin 時的客戶端 MCP 註冊，不修改標準即達成。
    - **Pull 模式 auto-trigger**：`system-skill-dispatcher` 常駐列出非系統 skill 清單，Agent 呼叫 `activate_skill` 寫入 `session.active_skills`，下一輪 `SkillLayer` 以 `header ∪ active_skills` 注入（仿 `connect_mcp_server`）。
    - **打包分發**：`GET /v1/skills/{id}/export`（`.skill` ZIP）+ `POST /v1/skills/install`（URL 安裝，`ALLOWED_SKILL_DOMAINS` SSRF 白名單 + `follow_redirects=False` + zip-bomb 防護 + `.bak` 原子覆寫）。前端 ToukaChat 新增匯出按鈕與 `SkillInstallModal`。
    - **Metadata 子欄位相容**：Touka 擴充欄位（`display-name`/`category`/`author`/`is_system`）收於 frontmatter `metadata:` 子欄位，真正通過 Anthropic `quick_validate`。
    - **Dispatch 自動召喚（ADR-0067）**：`dispatch_initialize_mission` 加 `auto_invoke` 參數；mission 建立後依 `ToukaDispatch/config/dispatch_hooks.json`（Configuration-as-Code 白名單）以 `subprocess`（`shell=False`、env-only 傳一次性 `mission_token`、whitelist 淨化子環境）fire-and-forget 召喚外部 AI，Touka Agent 不再手寫 bash。新增 executor 只改設定不改程式碼。
    - **安全**：全域 `DISPATCH_TOKEN` 主金鑰絕不外洩；env whitelist 預設拒絕（連無關鍵字密鑰也擋）；command 全白名單 list 零注入；fail-closed。詳見 [SECURITY.md](../../SECURITY.md) A4/A5/A6。
    - **測試與守衛**：新增 skill 標準化測試（`test_skill_parser`/`test_skill_service_dir`/`test_skill_progressive`/`test_skill_dispatcher`/`test_activate_skill`/`test_skill_layer_*`/`test_skill_export_import` 等）與 `test_dispatch_hooks.py`（18 個，ADR-0067）；全體 **1127** pytest 全綠；guard_all 27/27；前端 Vitest 全綠；冒煙 14/14。

-   **2026-05-21**: **三次安全審計 P1~P29 — 管道加固、身分/授權強化、基礎設施鎖定 ⭐**
    - **安全標頭主權**：全域 `SecurityHeadersMiddleware` 注入三個強制安全標頭（nosniff / X-Frame-Options: DENY / strict-origin-when-cross-origin）。所有回應自動附加，不得在端點層覆寫。
    - **請求體大小主權**：`RequestSizeLimitMiddleware` 強制上限 10MB（`MAX_REQUEST_BODY_BYTES`）。超限回 413 `REQUEST_TOO_LARGE`，防止記憶體耗盡攻擊。
    - **Cookie Secure 預設生產安全**：`SECURE_COOKIES` 預設改為 `True`；開發環境必須明確在 `.env` 覆蓋 `SECURE_COOKIES=false`。嚴禁在生產環境關閉此旗標。
    - **Refresh Token Replay 防護**：Refresh token 輪換加入 `jti` (UUID) claim；`User.refresh_token_jti` 欄位儲存當前合法 jti；舊 token 重用立即撤銷全部 session。
    - **速率限制擴展**：`/auth/register` 與 `/auth/refresh` 加 IP 滑動視窗速率限制（與 `/auth/login` 一致）。新開放的認證端點必須同步設定限流。
    - **Debugger 擁有權檢查 (P7)**：LDH 本地信任分支中，assume Debugger 身分前必須確認 `header_agent_id in identity.owned_agents`（admin bypass）。嚴禁允許 localhost 任意 assume 無擁有權的 Agent。
    - **並發鎖定擴展**：凡涉及「讀取—修改—寫入」共享狀態的模組（connections、autonomy、permission_service、session append）均必須持有 `threading.Lock` 或 `asyncio.Lock`。不得裸露 TOCTOU 視窗。
    - **Session TTL 主權**：Session 活動時間記錄於 `last_activity_at`；90 天不活躍 Session 於 lifespan startup 自動清除（`cleanup_expired_sessions()`）。
    - **觀測端點認證**：`/logs`、`/memory`、`/tools`、`/tools_stats` 及其子路由不得列入 allowlist 公開。所有非健康檢查的觀測端點均需帶有效身分。
