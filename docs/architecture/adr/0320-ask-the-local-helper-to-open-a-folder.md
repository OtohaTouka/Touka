# ADR-0320：從 Touka 設定頁請本機小幫手開放資料夾

- 狀態：✅ 已實作。一頁計畫由維護者核准（2026-11-16，小幫手第二版 PR 3），細節設計審四輪。
- 日期：2026-11-17
- 決策者：維護者
- 相關：[ADR-0312](0312-local-helper-for-host-files.md)（本機小幫手第一版）、[ADR-0317](0317-local-helper-follows-touka-approval-mode.md)（配對鑰匙與蓋章；本 ADR 實作它保留的 `request_open`）
- 影響範圍：`ToukaProxy/src/routers/local_bridge.py`、`src/models/local_bridge.py`、`src/services/local_bridge.py`、`src/utils/local_bridge_signing.py`、`src/utils/csrf_guard.py`、`config/errors.json.example`、`ToukaChat` 設定頁（`useLocalOpenRequest`、`LocalHelperOpenFolder`）、`ToukaLocal/touka_local/`（`open_request.py` 為新檔；`service.py`、`approval.py`、`grants.py`、`signing.py`、`protocol.py`、`app.py`、`view.py`）、`ToukaLocal/install.py`

## 背景

開放資料夾原本只能在小幫手的主視窗按「開放」、用資料夾選擇器挑。維護者希望在 Touka 的設定頁就能送出請求，再到小幫手的視窗確認。

難處：送出請求的不能是靈魂或代理人；冒充 Touka 的程式不能一直跳視窗騙人按；Touka 被攻破時，不能藉這個請求探出電腦上哪些位置有檔案。

## 決定

### 1. 誰能送：配對的人本人，從設定頁

- 新端點 `POST /local-bridge/open-requests`（`/v1` 也有），參數只有路徑（1～1024 字，不能有控制字元）。路徑規則（絕對路徑、不能開放的位置）全部由小幫手判斷，Touka 不重複一份。
- 只給人類管理員（`require_admin_human`），而且要是產生配對碼的那個人（`LOCAL_HELPER_NOT_PAIRED_HUMAN`，403）；還沒配對回 `LOCAL_HELPER_NOT_PAIRED`（409）。人和鑰匙從配對紀錄的同一次讀取拿。
- 一定要帶信任的 Origin（新的純函式 `require_trusted_origin`；其他端點用的 `verify_origin` 不變）。這只是多一層防護：不是瀏覽器的程式可以自己帶 Origin，真正的關卡是身分加上比對配對的人。
- 模型的工具合約沒有 `request_open`，測試釘住。

### 2. 協議不升版，請求帶章

- 動作 `request_open`（ADR-0317 已保留）；參數正好是 `{"path": ...}`。
- 一定帶 `decision`：Touka 每次新產生的一次性號碼、`digest` 與 `shown` 都是路徑的指紋、`decided_by` 是 `owner_request`、章用配對鑰匙蓋（`act` 是 `request_open`，和清單的章不能互用）。舊配對沒有鑰匙時回 `needs_new_pairing`，不送出。
- 舊版小幫手收到帶決定的開放請求回 `bad_request`，不會跳視窗；設定頁說「小幫手版本太舊」。小幫手版本升到 0.2.0。

### 3. 小幫手：能不能開放都跳視窗

驗章通過的請求，不論位置能不能開放，一律跳視窗；人動手或 120 秒到之前，Touka 收不到任何和位置有關的回報。順序：

1. 停收中（第 4 點）→ `open_paused`。
2. 驗章：參數、長度、章、指紋不對，或一次性號碼用過，都回 `bad_signature`；小幫手沒有鑰匙回 `needs_new_pairing`。不正規化路徑。
3. 先佔住核准視窗（已有視窗或冷卻中回 `approval_busy`／`approval_cooldown`，和位置無關）。
4. 再檢查路徑（和主視窗按「開放」同一套規則）。讀不到、出錯都算不能開放。
5. 把結果放進視窗：能開放的讓人選權限（預設只能看）、拒絕是預設焦點、核准 1.5 秒後才能按（從畫出視窗起算）；不能開放的寫原因、只有「知道了」。路徑看不見的字元換成記號。

- 視窗時間固定 120 秒，不用 Touka 給的時間；Touka 等 150 秒。
- 開放請求不理會 Touka 撤回，視窗留到人決定或時間到。關掉設定頁也不會撤回。
- 人按核准就加進名單，不經 Touka 確認（人看著完整路徑決定）。
- 回報：核准 `ok`（名稱與權限）；拒絕與「知道了」都是 `not_opened`；時間到都是 `no_decision`；核准後才加不進去的是 `not_openable` 或 `io_error`。不能開放的原因只顯示在小幫手的視窗。
- 主視窗訊息列不顯示 Touka 送來的路徑。

### 4. 停收

連續 3 次沒核准（拒絕、知道了、時間到，或換配對、小幫手被看見時視窗被收掉），停收 10 分鐘；核准一次就歸零。主視窗顯示恢復時間與「現在恢復」按鈕，重開小幫手也會恢復。只記在記憶體。

### 5. 設定頁

- 小幫手配對而且開著時，設定頁多一個「請小幫手開放資料夾」區塊：貼上路徑（自動去掉前後空白與一組引號）、按鈕、等待中的提示、結果。
- 先看 HTTP 狀態：403、409 才查錯誤碼；422 是路徑不合格式；401、5xx、網路錯誤當沒送出。自己最多等 170 秒，等太久說「可能已經開放，請到小幫手看名單」。

## 後果

Touka 控制得到的輸入都檢查過，和位置能不能開放無關：

| 輸入 | 處理 |
|---|---|
| 撤回（`cancelled`） | 開放請求忽略 |
| 等待時間（`decide_within`） | 開放請求忽略，固定 120 秒 |
| 讓小幫手被看見的掛載路徑、回 401 | 收掉視窗、不回報、算一次沒核准，兩種位置一樣 |
| 回 409、格式錯誤、連不上、拖到逾時 | 小幫手變成需要升級或離線，視窗留著 |
| 回報端點回 200 或 410 | 開放請求不看 |
| 同時送很多個 | 第一個佔住視窗之後才檢查路徑，其餘回 `approval_busy` |
| 路徑字串 | 只決定視窗樣式，人看得到 |

- Touka 被攻破時有鑰匙，可以一直送開放請求：每個都要人在電腦上看到視窗，預設拒絕、預設只能看，連續 3 次沒核准就停收 10 分鐘。被攻破的 Touka 不能不經人看到就知道開放資料夾以外的位置能不能開放。
- 正常使用者打錯路徑 3 次也會停收；主視窗有「現在恢復」。
- 已接受的風險：小幫手重開後，被截到的舊請求可以再送一次（要能監看本機 loopback 或 Touka 已被攻破，而且只會跳出人自己送過的路徑，仍受停收限制）；人動手之後，Touka 從 `not_opened` 和 `ok` 知道人怎麼決定（人已看過視窗）；既有的管道：被攻破的 Touka 可以藉 `host_mount_roots` 試出小幫手與 Python 裝在哪裡（字串比對、不讀磁碟，ADR-0312 就有）。
- nginx 範例的 REST 預設 60 秒短於 150 秒，但那份設定只用在雲端部署；小幫手只連本機的 Touka，不改。

## 不採用

- 請求帶時間戳、小幫手拒絕太舊的：WSL2 的時鐘在電腦睡眠後可能漂移，誤拒很難懂。
- 設定頁不送路徑、改由小幫手跳出資料夾選擇器：背景程式跳出的系統對話框可能被瀏覽器蓋住，人找不到；一頁計畫核准用路徑。
- 開放後要 Touka 確認：人看著完整路徑決定，不需要。
- 權限由設定頁決定：一頁計畫寫權限在小幫手裡選。
- 升協議版本：保留的動作和既有欄位夠用。
- 不能開放的位置直接回細分的代碼：被攻破的 Touka 能藉此不經人看到就探出檔案位置。
