# ADR-0306：換家的狀態與舊家唯讀

- 狀態：🚧 部分實作（PR 2a：交接紀錄、設家狀態機、舊家唯讀與刪除、交接前的主線）。交接工作本身（舊家歸檔、退任摘要、子對話回報、換家標記）在 PR 2b，畫面在 PR 3，各自補進本 ADR。一頁計畫由維護者核准（路線圖 3d，2026-11-07），計畫經五輪審查。
- 日期：2026-11-08
- 決策者：維護者
- 相關：ADR-0305（靈魂前情與主線；本 ADR 接著做換家）、ADR-0301（家標記不算版本；本 ADR 修訂決定 2 的「心跳跑到一半換家」）、ADR-0092（滑動視窗剪裁）、ADR-0257（歷史資料界線）、ADR-0260（家對話外送白名單）、ADR-0264（剪下的對話歸檔）、ADR-0267（活動時間軸的生命週期前例）、ADR-0276（對話歸屬與範圍版本）、ADR-0277（跨來源查對話）、ADR-0302（聊天側剪裁）、ADR-0078（失效不沉默）、ADR-0231（對話保存的版本）。
- 影響範圍：`ToukaProxy/src/utils/home_transitions.py`・`src/utils/async_db.py`・`src/services/proxy_service.py`・`src/services/mainline_service.py`・`src/services/soul_service.py`・`src/routers/heartbeat.py`・`src/routers/ui_sessions.py`・`src/routers/ui_interjections.py`・`src/services/agent_reset/`・`src/services/gdpr_export_service.py`・`src/services/context_snapshot_service.py`＋`ToukaProxy/config/errors.json.example`＋`ToukaChat/src/lib/error_codes.ts`・`src/locales/`。

## 背景

以前換家只清家標記（`async_db.set_home`），舊家變成普通子對話：可以繼續聊、可以刪、可以換靈魂，它的內容就此離開主線。Owner 2026-11-06 定下的方向是「換家＝搬家」：舊家原文進舊對話庫、摘要併進前情、舊家唯讀；新家第一次被使用才真正交接，之前改回去當沒換過。

PR 2a 先做換家的狀態：記下誰換到誰、舊家從此唯讀、交接完成前不能刪。交接工作本身留給 PR 2b；2a 合併後到 2b 合併前，舊家原文照樣帶在主線裡，靈魂接得上。

## 決定

1. **兩張新表**（`ui_sessions.db`，和對話同一區，`async_db.init_db_async` 呼叫 `home_transitions.create_tables` 建立）。
   - `soul_home_transitions`：每次換家、取消家記一筆：編號、靈魂（正式 ID）、範圍版本、舊家、新家（可空）、新家已開始用、狀態（待交接／交接中／完成／取消／失敗）、做到第幾步、失敗次數、退任摘要待補、「舊家已由第 n 筆交接」、時間（epoch 毫秒）。「舊家已由第 n 筆交接」的紀錄只記新家是誰：不算舊家、不擋刪除。沒有可改指的紀錄時設家（第一個家、舊家已交接完、設回的正是交接中的那段）也記一筆，舊家＝新家、n 指那筆交接或 0（沒有前任），用來追蹤新家有沒有用過。
   - `soul_child_report_marks`：子對話的回報寫到哪（對話、靈魂、範圍版本、目前節點）。2a 只建表；升級那次（表這次才建）把既有子對話的位置設在當下內容（只收字串的目前節點，由 SQLite 取值），不補寫歷史，之後新建的子對話沒有位置（全部算新內容）。建表與初始位置在同一個明確交易，中途失敗下次啟動整個重來。2b 寫回報時用。
   - 刪掉一段對話時，同一個交易刪它的回報位置、把它當舊家的已完成或取消紀錄失效（同一個編號之後重用時不是舊家）；它當新家的紀錄不動，前面那段舊家照舊唯讀。
   - 失效同前情：同名重建與還原備份把範圍版本改成 0（`invalidate_agent_sessions`、`invalidate_restored_sessions`）。失效的紀錄不處理、不算舊家、不擋刪除，舊靈魂或不可信的還原對話不會被摘要進前情（ADR-0276、0277）。
   - 所有 SQL 是固定字面量（禁令 24）。
2. **設家、取消家照狀態對照表改紀錄**，和家標記在同一個交易（`home_transitions.apply_home_change`；設家不拿靈魂鎖）：

   | 現在 | 動作 | 結果 |
   |---|---|---|
   | 家 A，沒有紀錄 | 設 B | A 退任；新紀錄 A→B（還沒開始用） |
   | A→B，B 還沒開始用 | 設 A | 取消 A→B；A 恢復成家（當沒換過） |
   | A→B，B 還沒開始用 | 設 C | 紀錄改成 A→C；B 回到普通子對話 |
   | A→B，B 已開始用（待交接或交接中） | 設 A | A 恢復成家；A→B 照樣要做，另加 B→A |
   | A→B，B 已開始用 | 設 C | A→B 照樣要做，另加 B→C |
   | 家 A（用過，或升級前就是家） | 取消家 | 紀錄 A→（無） |
   | 原本沒有家、舊家已交接完 | 設 X | 記一筆只記新家（X→X，第 0 筆或那筆交接）；X 沒用過就取消家或改設別段，當沒換過（X 回到普通對話）；用過之後離開照一般規則加紀錄 |
   | A→B，B 還沒開始用 | 取消家 | 紀錄改成 A→（無） |
   | 不是家的那段 | 取消家 | 什麼都不做（以前對任何一段按取消家都會清掉家） |
   | A→（無），還沒開始交接（步驟 0） | 設 D（含心跳建家） | 紀錄改成 A→D（還沒開始用）；設回 A 則取消；有好幾筆（既有資料兩個家）一起改 |
   | A→（無），交接中 | 設 D | 進行中的不動；另加 A→D，標「舊家已由第 n 筆交接」（2b 只寫換家標記） |
   | A→（無），交接中 | 設 A | A 立刻恢復成家，不加新的交接，只記一筆 A→A（只記新家）追蹤有沒有用過：沒用過就離開，照舊是那筆交接的舊家 |
   | 已完成交接的舊家 A | 設 A | A 回任；原本的家另加一筆 |
   | A→（無），交接失敗，或做到某一步又回到待交接 | 設 D、設 A | 同交接中（失敗的會再試、仍算舊家） |
   | 既有資料有兩個家 | 設 X | 其他家各加一筆，依序排隊；X 還沒開始用時改設別段，指向 X 的紀錄一起改寫 |

   內部頻道（`touka.` 開頭）與退休頻道不能設成家：頻道編號固定，換走、刪掉重建會一出生就是舊家。升級前就當家的內部頻道離開時（換家或取消家）不建紀錄，頻道回到普通頻道，不會變成設不回、刪不掉的舊家。

3. **「是不是舊家」由紀錄推導**：某筆有效、沒取消、不是「只記新家」的紀錄的舊家，而且現在不是家。設回家立刻不算舊家，不必改旗標。舊家交接完成前（待交接、交接中、失敗，或退任摘要待補）不能刪；完成後可以刪，但照舊唯讀。
4. **新家「開始用」在交易裡記**（之後改回去就不能當沒換過）：網頁在准入交易（`admit_ui_stream`）裡記；IDE 舊路徑、SNS 家模式、外部相容路徑沒有准入交易，在共同入口快速檢查通過時記（之後被 hook 擋下也算開始用）；心跳在 `/awaken`（家模式、頻道、指定對話）與 `/retrigger` 開新的一輪之前記。無痕不記。只記在「新家目前就是家」的紀錄上。共同入口記之前先確認請求者能用這段對話（和存檔同一套歸屬與權限規則，`_session_access`）：不能用時什麼都不寫、不回是不是舊家，交給後面的層照原樣拒絕；沒有身分的內部路徑（SNS 閘道）照舊。能驅動這段對話（前綴正規化後）的靈魂的請求者也算能用：舊前綴（`ToukaSoulX`）的列擁有者比對會失敗，後面各層卻會正規化後代打寫入；這也讓 DebugAgent、admin 代打別的靈魂時在舊家被擋，不再呼叫模型。只有這一輪存得進去的請求者（通過存檔檢查，或是人類）才記開始用：DebugAgent、代打別的靈魂的非人類身分存不進新家，不記，人工測試也不會改到別的靈魂的紀錄。
5. **舊家不能開新的一輪**：
   - 共同入口 `proxy_service._run_request` 在 `pipeline.execute` 之前先擋，hook、組主線、記錄這一輪都不會先跑；網頁、IDE、外部相容路徑、SNS 都經過這裡。對話編號和 MonitorLayer 用同一個解析（`monitor.turn_session_id`：本文，再看 `x-touka-session-id`、`x-toukachat-session-id` 標頭）。網頁在准入交易裡再驗一次，作為最後判定。
   - 新增插話（列出、收回照常，換家前就在跑的回覆收得回插話；無痕串流不查，無痕不碰資料庫，在舊家開新的一輪已由共同入口擋）、心跳開新的一輪（家模式讀到家之後才被換走、預設頻道、指定這段、`/retrigger`）、換靈魂也擋。SNS 被舊家擋下時外人訊息不存進舊家。
   - 交接開始前，一般存檔不擋（分不出收尾保存和編輯），改名、收尾保存、「僅重試保存」照舊；交接開始後（第二段：這段舊家最新一筆有效紀錄是交接中、完成、失敗或做到某一步；以前那一任或較早那筆還在交接、回任用過再換走時，這一任還沒開始，較早那筆和新內容的一致性交給 2b 開始交接前等收尾保存），存檔閘（`_save_session`）擋所有內容寫入。
   - 錯誤碼兩個：`SESSION_OLD_HOME_READ_ONLY`（1223，「舊家，請先設為家」）、`SESSION_OLD_HOME_NOT_DELETABLE`（1224，「舊家交接完成前不能刪」），都是 409。刪除在路由與刪除閘都擋。
   - 讀不到紀錄時讓這一輪失敗、不放寬（ADR-0078），回 `SESSION_SAVE_FAILED`（共同入口、新增插話、心跳）。
   - 畫面還沒做舊家（PR 3）之前，前端收到一般形狀的 `SESSION_OLD_HOME_READ_ONLY` 時照 hook 擋下的做法（`useOldHomeNotice`）：顯示專屬訊息、把這一輪從樹裡拿掉再存回、文字放回輸入框。
6. **心跳建家走同一套紀錄**：新列寫入的同一個交易裡（`new_home_after_write`，經 `conditional_save_session(after_write=...)`）確認沒有別的家、照上表改紀錄；讀家之後有人設了家就整筆退回，不做出兩個家。
7. **交接前的主線**（`mainline_service`）：還沒交接完的舊家原文（待交接、交接中、失敗；已經又是現任家的不放）依紀錄順序排在家原文前面，各自包一層 `source="old_home_pending_handover"` 的歷史資料界線、每則標時間。帶家原文的地方都帶，網頁版家本身與心跳在家時也帶（新家第一輪就接得上）；心跳在子對話、無痕不帶。總量有上限（`soul_service.OLD_HOME_TOKEN_BUDGET`，8,000 估算 token）：從最新的舊家尾端往前收，額度用完就停；每段尾端從使用者那則開始（Claude 規定送出的第一則要是使用者，截在 AI 回覆上會每一輪都 400），跳過的算進省略數；省略過的那段第一則前面寫一行「前面還有幾則，原文留在舊家」；一則都帶不進去的那幾段合成一行「另有幾段共幾則沒有帶」，併進第一段帶得進去的舊家開頭，全部帶不進去時單獨送一則（使用者角色、在界線裡；不每段一則，也不多出連續的使用者訊息）（滑動視窗把這些當成剪不掉的部分，沒有上限時新家每一輪都被剪到最少）。讀紀錄表失敗時和讀家一樣：這一輪失敗，心跳照樣送出；某段舊家那一列讀不出來時記 warning、跳過那一段。
8. **對話清單**（`GET /ui/sessions`）每段多一個 `is_old_home`。紀錄表讀不到時清單照常、標記當成否（記 warning）；擋寫入的各閘照舊讀不到就失敗。
9. **生命週期**（照 ADR-0267、0305 前例）：重置清除與殘留自檢（`StorePurger("home_records")`，在 `PROXY_STORES`、和對話與前情同一區）、刪靈魂前檢查（`assert_prelude_cleared` 一起查，409 帶 `home_records`）、GDPR 匯出（`agents/<id>/home_handover.json`，只有對話編號與狀態）。
10. **審查第 1 輪的修正**（J1–J22，見計畫資料夾的審查紀錄）都寫進上面各條；行為上最大的是：標頭帶對話編號也擋、共同入口先確認請求者、交接完成或失敗之後舊家照樣唯讀、舊家原文有上限。
11. **審查第 2 輪的修正**（K1–K16）也寫進上面各條：交接已開始只看最新一任、刪對話不讓前面的舊家失效、舊家原文從使用者那則開始且放不下時留說明、舊前綴的對話照樣擋、頻道離開不建紀錄、插話最後再驗一次串流、取消家後的好幾筆一起接上新家、清單標記讀不到不影響清單。
12. **審查第 3 輪的修正**（L1–L9）也寫進上面各條：交接已開始一律只看最新一筆、沒有前任時設的家也追蹤有沒有用過（第一個家沒用過就取消當沒換過）、做到某一步的交接算已開始、說明合成一行、存不進去的請求者不記開始用、無痕插話不查舊家。
13. **PR 1 審查留下的**：`soul_service.inject_home_messages` 的家訊息改成必填，拿掉自己讀家的分支與 `async_db.get_home_messages`；安全測試改走真正的注入路徑（`inject_mainline`）。

## 取捨與影響

- 換家之後舊家不能聊、不能刪、不能換靈魂；要繼續那段就把它設回家。新家還沒開始用時設回去等於沒換過。
- 2a 合併到 2b 合併之間交接不會開始：舊家原文一直帶在主線裡（請求變大），舊家也一直不能刪。這段期間不發版（計畫寫明）。
- 每一輪多一次讀紀錄（有索引）；存檔多一次查詢。
- 取消家只對現任家有作用，修好以前按任何一段都會清掉家。

## 已知限制

- **切分存入舊對話庫不在後端擋**：那個端點不帶對話編號，後端分不出是哪一段；接著的存檔在交接開始前本來就不擋，切出去的部分已經在舊對話庫，不會遺失。PR 3 在舊家不顯示這個操作。
- **收尾等待**：剪裁觸發點遇到不是家的對話會立刻丟掉收尾等待（`dispatcher._closing_save_arrived`）。交接開始前要等舊家的收尾保存，這要等交接工作，留給 PR 2b。
- **IDE 舊路徑**沒有准入交易：快速檢查通過到設家之間的小空檔，當作「換家前就開始的回覆」放行。心跳同一類：舊家檢查和寫初始提示不在同一個交易，中間剛好換家時整次多脈衝跑在舊家；換家前就開始的多脈衝心跳，剩下的脈衝（排程設的次數；`/retrigger` 最多 5 個）照樣寫進舊家，算「那一輪寫得完」（交接開始後存檔閘才擋）。
- **每一輪都讀出全部還沒交接完的舊家**再套上限：2a、2b 之間交接不會開始，每換一次家多一段，成本跟著舊家總大小變大（這段期間不發版）；上限固定 8,000、不看模型的上下文大小，小窗口模型換家後每輪多最多 8,000。2b 再看要不要只讀尾端。
- 舊家最後一則是使用者（例如回覆失敗的那一輪）時，接著的下一段或家原文也從使用者開始，會有連續兩則使用者訊息；轉 Claude、Gemini 時合併，OpenAI 相容路徑原樣送出（家原文接在請求前面本來就可能這樣）。
- **交接開始後在舊家送出**（2a 碰不到）：網頁先存使用者那則就被存檔閘擋，跳通用的保存失敗、這段的存檔停住；IDE 收到舊家擋下只顯示「Proxy Error: 409」。PR 2b、PR 3 處理（送出前先擋、IDE 讀錯誤碼）。
- **刪除靈魂前的檢查**：升級時替既有子對話建了回報位置，「有升級前的對話、但沒有記憶、活動紀錄與前情」的靈魂現在刪除前也要先重置（重置會一起刪對話）；聊過天的靈魂都有活動紀錄，影響很小。
- **畫面**：舊家的唯讀畫面、側欄標示、確認視窗，刪除與中斷重跑的錯誤文字，在舊家換了模型再送的邊角，取消家時前端把同一個靈魂的家全部標成不是家（畫面過期時和伺服器不一致），都在 PR 3。准入那一刻才剛換家的競態走保存結果的形狀，畫面照保存失敗顯示。
- **SNS 家模式、SNS 獨立頻道與 SNS 群聊**（對方都是外人）的請求也帶舊家原文（同家原文與前情，SECURITY.md 殘留風險）；群聊白名單裡別的擁有者的靈魂被外人 @ 時也帶，2b 決定子對話回報進不進 SNS 時一起看。
- 失敗紀錄在 `/v1/stats` 的顯示、24 小時自動再試、退任摘要的補寫都在 PR 2b。
- `is_old_home` 只在對話清單有，單一對話的快照沒有（`SessionDocument` 是嚴格模型，加欄位會動到版本計算的輸入）；PR 3 用清單。
- 一個靈魂只能有一個家的資料庫唯一限制不做（既有資料可能已有兩個家），由設家與心跳建家在交易裡處理。

## 驗證
