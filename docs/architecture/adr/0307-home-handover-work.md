# ADR-0307：換家交接工作與子對話回報

- 狀態：✅ 後端已實作（路線圖 3d PR 2b）；畫面在 PR 3。一頁計畫由維護者核准（2026-11-07）。
- 日期：2026-11-08
- 決策者：維護者
- 相關：ADR-0305（靈魂前情與主線；本 ADR 修訂「退任摘要不合併」）、ADR-0306（換家的狀態與舊家唯讀；本 ADR 做它留下的交接工作）、ADR-0092（滑動視窗剪裁）、ADR-0264（剪下的對話歸檔）、ADR-0078（失效可觀察）、ADR-0302（收尾保存）
- 影響範圍：`ToukaProxy/src/services/home_handover.py`・`src/services/soul_locks.py`・`src/utils/home_handover_db.py`・`src/services/dispatcher.py`・`src/routers/heartbeat.py`・`src/routers/stats.py`・`src/services/soul_prelude_merge.py`・`src/services/soul_prelude_service.py`・`src/services/mainline_service.py`・`ToukaChat/src/lib/providers/SessionListProvider.tsx`

## 背景

ADR-0306 記下誰換到誰、舊家唯讀、交接完成前不能刪，交接工作本身留到這裡。沒有這一步，舊家原文會一直帶在主線裡、舊家也一直不能刪。

## 決定

1. **觸發只在禁令 28 的兩處**，都是背景排程，不拉長回覆或心跳：
   - 聊天一輪存好之後（`dispatcher._maybe_trim_after_chat`，網頁與 IDE；無痕不走這裡）。綁靈魂的對話都排：家、子對話、舊家。舊前綴的寫法算同一個靈魂。沒有靈魂的對話不排。
   - 心跳結束時（`finally`，至少完成一個脈衝、開跑之後沒被重置或刪除）。排的時候這次心跳已經拿掉登記。
   - 剪裁失敗也排：交接和剪裁是兩件事。
2. **每個靈魂最多一個維護在跑**（`home_handover.schedule`）：跑的時候再來的只留記號，跑完再檢查一次。整次拿靈魂鎖（`soul_locks.soul_lock`，和前情合併共用）；鎖的順序是靈魂鎖在最外層 → 剪裁的對話鎖 → 存檔的對話鎖 → SQLite 交易，模型呼叫都在交易外。重置或刪除中不做，每個寫入都再查一次。
3. **交接依紀錄編號一筆筆做**。
   - 新家還沒開始用的紀錄不做（改回去要能當沒換過）。沒有新家（取消家）的、已開始用的、做到一半的才做。
   - 舊家還有回覆或心跳在跑、或收尾保存還在等（聊天的收尾等待現在舊家也等），這次到此為止、等下一次觸發；舊家已經又是現任家時不等。
   - 認領和之後每一步的交易都核對狀態、步驟、新家、開始用沒變（設家不拿靈魂鎖，會改寫還沒開始的紀錄）。
4. **一筆紀錄的步驟**（`step` 記做到哪，中途停下從下一步接著做；舊對話庫只新增、段落有唯一索引，重做不重複）：
   1. 舊家整棵樹進舊對話庫：所有節點帶 `parentId`，插話併進內容，工具步驟留在附註。舊家已不存在時寫一行「原文已刪除」，這一筆完成。
   2. 退任摘要（輸出上限 2,000）。舊家已經又是現任家時標「待補」；前情摘要關閉或失敗時寫一行來源註記。
   3. 子對話回報（前 5 段，最多同時 3 段）。
   4. 一行換家標記。
   5. 完成。
   - **只記新家的紀錄**只寫換家標記，不讀它記的舊家（可能已刪或已是普通對話）；同一筆交接指向同一段的只寫一行。
5. **失敗**：累計三次標成失敗、寫一行註記、繼續做後面的；沒滿三次回到待交接、步驟保留。失敗的每次啟動後第一次觸發、或滿 24 小時再試。失敗紀錄在 `/v1/stats` 的 `failed_handovers` 看得到（只列 `can_access_session` 放行的靈魂），舊家在這段期間照舊唯讀、原文照舊帶在主線。
6. **補寫退任摘要**：佇列做完之後，標「待補」的舊家不是現任家、也沒有別筆還沒完成的紀錄時補寫；補寫前再歸檔一次（補上歸檔之後新增的節點）。
7. **子對話回報**（`child_report`，輸出上限 800）：候選是綁這個靈魂、不是家、不是舊家、不是頻道的對話，目前節點和回報位置不同，而且沒有回覆或心跳在跑。
   - 時機：交接時寫前幾段；另外每 30 分鐘最多檢查一次 6 小時沒動、有新內容的（候選要解析每段子對話的內容，不必每一輪都做），一次最多 5 段。
   - 位置失效（範圍版本 0）跳過；沒有位置的只有範圍版本 1 的對話算全部新內容；換過靈魂時把位置移到當下、不補寫換之前的內容；位置不在目前路徑上（換了分支）時整條路徑算新內容。
   - 段落和位置同一個交易；交易裡再確認對話還在、還綁同一個靈魂。沒有對話內容的只移位置、不花模型。
   - 前情摘要關閉時不寫；摘要失敗時位置不動，這個靈魂冷卻 6 小時（記在記憶體）。
8. **SNS（維護者 2026-11-08）**：SNS 獨立頻道、SNS 家模式、SNS 群聊的請求不帶子對話回報；家原文、剪裁摘要、舊家尾端照舊。吃進回報的合併段來源欄記 `#child-reports`，SNS 請求連它一起排除（否則回報併進合併段之後就漏出去）。群聊白名單裡別的擁有者的靈魂被外人 @ 那題不在這裡，列在路線圖候選。
9. **修訂 ADR-0305 的合併規則**：
   - 退任摘要可以合併；否則比合併段舊的那幾段會被折掉、永遠看不到。一行來源註記照舊不合併。現任家自己的退任摘要不顯示，也不會被合併。
   - 同一來源被取代的舊版退任摘要一起標成已合併，不會重新出現。
   - 比合併段新的段落已達 `PRELUDE_MAX_SEGMENTS - 1` 時不合併（合併段一寫進去就被折掉）。
   - 維護寫了新段落之後，在靈魂鎖外試一次合併（合併自己拿靈魂鎖）。
10. **範圍版本**：失效的紀錄不處理。交接不看對話的 `session_scope_version`（2026-10-17 以前的家永遠是 0）。

## 影響

- 換家之後多幾次摘要模型呼叫（退任摘要一次、回報每段一次），都走前情摘要的設定與模型，關掉 `prelude_summary_enabled` 時不呼叫。
- 交接完成後舊家原文不再帶在主線，舊家可以刪。
- `/v1/stats` 多一個欄位（dict 折入，不動 openapi）。

## 已知限制

- **交接開始後在舊家送出**：畫面送出前會先存使用者那則，被存檔閘擋下（1223）時改跳舊家提示、內容退回存檔的樣子、文字放回輸入框，不留等人核對的保存失敗（`SessionListProvider.updateSession`、`StreamRegistryProvider.startStream`）；入口擋下之後存回被擋也一樣不算失敗。舊家的唯讀畫面在 PR 3。
- **回任期間被編輯的內容**：重新歸檔時，同一則內容不同的另存成版本（`legacy_store.archive`），不蓋掉之前歸檔的那份；只有下一筆交接或補寫退任摘要時才會重新歸檔，回任期間沒離開就不動。
- **一輪讀出全部還沒交接完的舊家**：ADR-0306 的成本照舊，交接開始之後舊家會陸續離開；交接卡住（失敗）時才會累積，`/v1/stats` 看得到。
- **吃進回報的合併段整段不給 SNS**：裡面的剪裁摘要也一起不帶，寧可少給。
- **冷卻記在記憶體**：回報失敗的 6 小時、失敗重試的「啟動後第一次」重啟就清掉，最多多試一次。
- **閒置回報靠下一次觸發**：靈魂完全沒有活動時，6 小時沒動的子對話要等下一輪或下一次心跳才寫回報。
