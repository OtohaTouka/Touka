# ADR-0173: ADR 修訂雙向一致守衛（Guard #28 第 4 檢查——單向修訂追蹤機器執法）

## 狀態

✅ 已接受（ADR 對齊回顧線 Phase 2 治本收官 R4；擴充 Guard #28 / [ADR-0068](0068-adr-integrity-guard.md)，非新增守衛檔）

## 日期

2026-07-22

## 背景

ADR 對齊回顧線 Phase 1（0001–0168，165 篇 100% 掃完）的橫貫結論：**「單向修訂追蹤」是本專案 ADR 最大宗漂移**——82 條確認漂移幾乎全屬此型態。後續 ADR（下稱 Y）在內文/相關段以「修訂／取代／反轉」宣告改寫某舊 ADR（下稱 X）的決策，且**前向連結齊全**；但被改的 X 未回頭加反向註記、仍標 `✅ 已接受`，直接打開 X 的讀者會誤解現行系統。

Phase 2 R1–R3 已逐受害者補反向註記（64 條 ADR、三處視型態同步：ADR 本體狀態行＋README 索引狀態欄），把存量單向對清零。但那是**一次性清理**；若無機器執法，未來任何新 ADR 只要「前向連結、忘了回標」就會重新累積同一種漂移。本 ADR 把該不變式結晶為守衛的常駐檢查。

專案「做得對」時本就是雙標的（模範：0063/0072 被退役時，狀態行＋README＋SECURITY.md 三處都標了反向 supersede 註記；0035 的 README 列有反向修訂註）——**問題是不一致，不是不能**。守衛的職責即把這個既有慣例從「靠自律」升級為「機器把關」。

## 決策與實作

擴充既有的 `scripts/guard_adr_integrity.py`（Guard #28，ADR-0068）加**第 4 檢查：修訂雙向一致**。因是同一守衛檔內新增一項檢查、非新增守衛，`guard_all` 守衛總數不變（維持 44）。

### 不變式

> 若 ADR-Y 以「反轉性動詞 + ADR-X 編號」正向宣告修訂/取代 X（Y≠X），則 X 的**狀態區**或 **README 索引列**必須回指 Y（存在反向註記）。否則報「單向修訂」FAIL。

### SSOT 與範圍（刻意收斂）

- **反轉性動詞集合**（`_AMEND_VERBS`）：`修訂／取代／反轉／汰換／廢棄／supersede(s/d)／amend(s/ed)`。這些宣告 Decision 被反轉，會使舊 ADR 讀者誤解現況＝高價值標的。
- **刻意不納入**：`延伸／延續／建基於／抽取／細分`。這些是「擴充」或「純檔案位移」而非決策反轉——反向註記仍鼓勵、但屬**選配**，不納閘。此收斂是為避免大量低價值假陽性（例如「抽取後檔案指標過時」不影響讀者對決策的理解）。

### 方向判別（避免把反向註記誤判為正向 cite）

正向宣告樣式只認「**動詞在前、ADR 編號緊接其後、中間無 by**」（`動詞　ADR-XXXX`）。下列三種天然不符本式，故掃全 ADR 內文＋README 列時，本專案 R1–R3 補的反向註記都不會被誤讀成正向宣告：

| 型式 | 例（示意，非本檔真實 cite） | 是否匹配 |
| :-- | :-- | :-- |
| 正向宣告：動詞在前 | `取代　ADR-NNNN` | ✅ 匹配（受詞在後＝真正向） |
| 反向註記：編號在前 | `ADR-NNNN　修訂：…` | ❌ 不匹配 |
| 反向註記：被動 by | `… by ADR-NNNN` | ❌ 不匹配（中間有 by） |
| 反向註記：冒號標籤 | `修訂：ADR-NNNN` | ❌ 不匹配（冒號非空白） |

### 反向註記驗證

對每個正向對 (Y→X)：X 的**狀態區**（檔頂至第一個「## 背景/上下文/決策」之前）或 X 的 **README 索引列**只要含指向 Y 的 `ADR-YYYY` 參照，即視為已補反向註記（滿足）。此為寬鬆判準（傾向少誤殺），因反向註記依慣例必落在狀態行。

### 逃生口

`AMENDMENT_BACKLINK_GRANDFATHER: frozenset[tuple[str, str]]`：正向宣告存在、但反向註記刻意不加（或無法加）的例外對 (Y, X)，每筆須註明理由。目前為**空集**——因 R1–R3 補完後活體零違規，無需 grandfather。

### 落地順序（紅→綠實證）

依 backlog 規劃，本檢查**在 R1–R3 文件修訂完成後才納閘**（否則守衛一建即紅）。實測：納閘時活體掃出 **6 個正向修訂宣告對**（0050↦0048／0092↦0035／0105↦0083／0117↦0071／0118↦0053／0151↦0118），**全數已有反向註記＝0 違規**，直接納閘無需任何 grandfather＝R1–R3 治本完整的機器證明。

## 後果

- **防復發**：此後任何新 ADR 若以反轉性動詞宣告改寫舊 ADR、卻未在舊 ADR 補反向註記，`guard_adr_integrity` 即 FAIL、擋下 commit——把「單向修訂追蹤」從最大宗漂移變成不可能再默默累積。
- **範圍取捨**：只納強反轉動詞＝可能漏掉「延伸/抽取」型的檔案指標漂移（那些由人工 R3 補、非機器強制）。這是刻意的精確度取捨（寧可少報也不淹沒於假陽性）。
- **維護成本**：新增真實 amendment 時作者須回標舊 ADR（本就是正確做法）；極少數確不需回標者登記 grandfather。
- **零行為碼**：純文件治本＋守衛擴充，不動任何生產碼路徑。
