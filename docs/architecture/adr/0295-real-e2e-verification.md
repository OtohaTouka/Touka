# ADR-0295：實際驗證：真前端、真後端、假模型

- 狀態：✅ 已實作（環境與 Hook 全部事件的路徑）。一頁計畫由維護者核准，計畫經 3 輪審查。
- 日期：2026-11-04
- 決策者：維護者
- 相關：ADR-0103（smoke 反死鎖）、ADR-0214（測試沙盒）、ADR-0243（臨時查驗限沙盒）、ADR-0292（Hook）。
- 影響範圍：新增 `tests/e2e/serve_real_backend.py`、`ToukaChat/playwright.real.config.ts`、`ToukaChat/e2e-real/`、`.github/workflows/e2e-real.yml`、`tests/lint/test_e2e_real_contract.py`；修改 `ToukaChat/package.json`（`test:e2e:real`）、`ToukaChat/knip.config.ts`、`ToukaChat/tsconfig.build.json`、`ToukaChat/scripts/lib/orphaned_tests_logic.ts`（`e2e-real/` 不是 Vitest 測試）；丙-2 新增 `tests/e2e/fake_mcp_server.py`。環境本身沒有改產品程式。

## 背景

單元測試全綠時，使用者照樣可能看到壞掉的畫面。試跑時就抓到兩個：模型回了讀不懂的內容時畫面只有空白泡泡；工具缺必要參數時畫面直接顯示程式錯誤。後端測試看不到畫面，前端測試的後端是假的，兩邊接起來的路徑沒有人走。

## 決定

1. **用使用者實際的方式走一次**：Playwright 開瀏覽器，走打包好的正式版畫面（`next build` 的 `out/`，不是開發模式）與真的 Proxy。模型是測試自己帶的假模型，收 hook 的也是測試自己帶的小伺服器。一個指令能重跑：`cd ToukaChat && npm run test:e2e:real`。
2. **花不到額度、碰不到真實資料**，三層都成立才算：
   - 後端跑在 `enable_smoke_sandbox` 裡，資料與設定都在系統暫存；啟動後再核對資料根與設定資料夾確實在沙盒裡，不在就中止。
   - 同一個函式按名稱樣式清掉金鑰類環境變數，並掛上網路防護：後端這個 Python 行程連本機以外的位址時擋下並記下來（缺口見「碰不到的地方」）。
   - 模型設定只有本機的假模型。設定裡的金鑰是標明不是真金鑰的固定字串，用來確認設定值不會出現在 hook 的事件內容。
3. **看結束碼，不看有沒有跑完**：測試結束時關掉後端的標準輸入，後端正常結束；atexit 清沙盒、把外連違規變成非 0 結束碼，Playwright 的 global teardown 看到非 0 就判整體失敗，錯誤訊息帶出被擋的目的地。逾時才強制結束，此時也判失敗，並且只刪後端印出來、核對過位置的沙盒路徑。teardown 也確認 `backend.log` 裡沒有測試帳號的密碼，因為它會傳成 CI 產物。
4. **設定走畫面，準備走 API**：設定 hook、觸發、看執行紀錄都走畫面。帳號與靈魂的準備，以及每個測試開始前的重置走 API，而且要排在瀏覽器登入之前（再登入會換掉瀏覽器的 refresh token）。
5. **固定埠 4901～4905**：前端建置時要寫死後端網址。被占用就報錯，不碰別的程式；後端與假 MCP 的埠先確認空著，否則會打到別人身上。
6. **輸出放在 repo 外面**：`E2E_REAL_OUTPUT_DIR`，預設系統暫存的 `touka-e2e-real`。每條路徑留截圖給審查員核對；trace 只在失敗時留，內容只有沙盒假資料與用完就丟的測試帳號。CI 把這個資料夾傳成產物，保留 7 天。
7. **放寬登入限制只限這個沙盒**：每次頁面載入都會換一次 refresh token，產品預設的次數上限不夠跑完整套，`serve_real_backend.py` 放寬 `AUTH_RATE_LIMIT_MAX`。產品設定不變。
8. **GitHub 上的自動檢查先不列為必過**：每個進 dev 和 main 的 PR 都跑，不用 secrets。瀏覽器測試可能不穩，連續 20 次沒有因為測試不穩而失敗，再由維護者決定要不要改成必過。
9. **模型探索打開，和一般 smoke 沙盒不同**：沙盒預設關掉模型探索，但假模型要靠它才進得了模型選單，所以 `serve_real_backend.py` 打開 `ENABLE_DYNAMIC_MODELS`；連線設定只有本機的假模型，探索也只會連到它。代價是 ADR-0103 提過的關機風險：探索留下的背景工作可能讓 Windows 上的關機卡住。這裡有 60 秒的關機逾時，逾時就強制結束並判失敗，不會默默過去。
10. **假 MCP 跑在後端的行程裡**：`tests/e2e/fake_mcp_server.py` 是真的 `MCPServer`，在 `serve_real_backend.py` 的另一個執行緒啟動，產品經真的 HTTP 連過去；一個工具用表單向人要資料，把答案回傳。測試結束時跟著行程結束。
11. **心跳帶權杖打喚醒端點**：這裡沒有跑排程服務。`global-setup.ts` 每次產生一個權杖，以參數交給後端、以環境變數交給測試行程，teardown 確認它沒有落到 `backend.log`。測試用的靈魂有 `heartbeat_awakening`，擁有者是登入過的沙盒管理員。設定 hook 與看紀錄照樣走畫面。

## 碰不到的地方

- 不經 nginx 與 Docker（部署路徑另有測試）。
- 不起心跳服務：喚醒由測試打端點（決定 11），排程與 Heartbeat 服務那一段沒有走到。
- 手動切分（`export_legacy`）只歸檔，剪是前端做的，沒有對應的事件，所以 PreCompact、PostCompact 只走自動剪裁。
- PostCompact 走心跳那條：聊天側的剪裁存不存得進去要看時間（見下面「實際驗證找到的既有問題」），所以聊天那條只驗 PreCompact 卡住時聊天照常。
- 精選 MCP 清單在沙盒裡是空的：清單不空時，打開設定頁就會去 npm 查下載量，那在這裡算違規，所以這份清單的畫面沒有走到。
- 這套不證明模型的行為：假模型只照標記回覆。
- 工具失敗時給 hook 的錯誤遮罩沒有走畫面：這條路徑走到的錯誤訊息本來就不帶路徑與憑證，遮罩由 `tests/unit/test_hook_tool_events_security.py` 驗。
- 隔離層級改變的 Notification 不走畫面：這個環境換不了隔離狀態，由 `tests/unit/test_isolation_status.py` 驗。
- 網路防護只管後端這個 Python 行程：後端再開的子行程不受管；Windows 上以 IP 字面值發起的 async 連線不會觸發它看的事件；瀏覽器與 Node 端的假伺服器都不在防護內。這些路徑若連外，這套不會變紅。
- 金鑰只按名稱樣式清除（`API_KEY`、`TOKEN`、`SECRET` 這類）：名字不符合的變數（例如只叫 `XXX_KEY`）會留在後端的環境裡。設定裡沒有真的模型連線，所以不會被拿去用，但環境裡有不代表一定安全，不要在跑這套的環境放這類變數。

## 實際驗證找到的既有問題

走丙-2 的路徑時看到的，都不是這批改動造成的（對照：在沒有這批事件的程式上重現；相關程式從公開版就沒有改過）。前兩個 2026-11-05 修好，由 `session-save.spec.ts` 驗；其餘還沒修，測試走人會走的恢復路徑（`lib/ui.ts` 的 `recoverSave`）。

- **設為家對話之後，同一段對話的下一則存不進去（2026-11-05 修好）**：這一頁新建的對話帶著「存檔裡不應該已有它」的標記，第一次存好之後沒拿掉；`set_home` 只是觸發點，任何讓畫面手上沒有版本、要重讀存檔的動作都會中（例如切對話時的清單重新整理）。換家時舊的家對話也有同樣症狀：畫面留著舊的家標記，和存檔對不上；設為家之後還沒再存過就換家或取消，畫面還會把家標記的更新擋掉（未確認的草稿不接受外部內容）。都一起修。
- **回覆結束 10 分鐘內重新整理頁面，回到那段對話，下一則存不進去（2026-11-05 修好）**：重新整理時畫面把已結束的回覆重播一次，再用那一輪的舊版本存檔，被擋下後就停住。現在存檔已比那一輪新就不重播；一樣新時照舊重播（原頁還沒存完整內容就關掉的情況）。10 分鐘是串流緩衝保留的時間（`STREAM_BUFFER_TTL_SECONDS`）。
- **聊天側的自動剪裁和畫面收尾的保存搶同一個版本**：回覆存好後後端開始剪裁，畫面同時送出收尾的保存，先存好的那邊贏。多半是剪裁輸，後端記 `ACID-B not confirmed`，對照時 4 次都這樣：沒有剪到，但歸檔已經做了，所以舊對話庫每次多一份相同的訊息。畫面那邊慢（收尾的保存晚到）的時候反過來（2026-11-06 GitHub 上 dev 與 #90 都遇到，本機把瀏覽器調慢也常這樣）：剪裁存好，畫面那次存不進去，下一則要先恢復；「僅重試保存」會把剪掉的內容寫回去，等於撤銷剪裁。畫面存不進去時，聊天那條測試先走恢復路徑再送（`hooks-lifecycle.spec.ts` 的 `sendAndWaitForModel`）。同一條測試在設家之後偶爾也會存不進去，那是設家和收尾保存撞在一起，2026-11-06 修好（家標記不算進版本，ADR-0301），和上面 2026-11-05 修好的那個不同。這裡是假模型，真的模型沒有測；心跳那條沒有畫面搶版本，照常成功。
- **模型失敗之後要按兩個按鈕才能繼續**：ADR-0231 把這種情況算成保存結果不確定，所以有「儲存工作階段失敗」的通知與保存提示，對只是模型失敗的情況太嚇人。丙-2 只補上「這一輪回覆失敗」的標示，保存規則沒有改。

## 試用經驗

- 這四個問題都是後端與前端各自的測試看不到的，要兩邊接起來、走第二則訊息才看得到；以前的路徑多半只送一則就結束。之後寫新路徑時，走完要再送一則。
- 計畫寫的是使用者看到的結果，實作時要回頭對照：順手修 1 我只改了後端，走到截圖才發現畫面沒有變。
- 同一個修正要想過同一類的輸入：順手修 1 第一版只處理 HTML 與非物件，審查才指出 `{}`、只有 `error` 的回覆仍是空白泡泡，假模型也要多一種回法。
- 要驗存檔就讀存檔：重新載入後畫面會接回已結束的串流、重新標示，所以「重新載入還看得到標示」沒有驗到存檔，審查才抓到。
- 改壞驗證的期望文字要寫到位：期望寫 `Error:` 時什麼錯都算，有一項是因為改壞時少送欄位才紅，沒有真的驗到「不等 hook」；另一項結束碼 0 沒變紅，是真的測試缺口。

## 後果

- 每個 PR 多一個約 5 分鐘的自動檢查（24 條路徑本機 2 分 10 秒，另加前端建置；測試變多會再長一些）。
- 不改依賴。CI 多用一個 Action（`actions/upload-artifact`），照 repo 慣例釘 commit。
- 之後改畫面或流程時，改到測試走的路徑要跟著改測試；選取元素用角色與使用者看得到的文字，所以改文案也可能讓它變紅。
