# ADR-0308：AI 問使用者問題沒等到回答時，這一輪停下

- 狀態：✅ 已實作。一頁計畫由維護者核准，經兩輪審查。
- 日期：2026-11-09
- 決策者：維護者
- 相關：取代 [ADR-0085](0085-ask-user-tool.md)「逾時 AI 續跑」；[ADR-0231](0231-session-persistence-outcomes-and-revisions.md)（工具步驟不送給模型）
- 影響範圍：`ToukaProxy/src/tools/builtin/interaction.py`、`src/utils/ask_user_stop.py`、`src/handlers/react_core.py`、`src/services/dispatchers/group.py`

## 背景

`ask_user` 等 10 分鐘沒回答時，工具回「以你最合理的判斷繼續」，模型就自己決定做下去。使用者沒回覆不算同意；讓 Touka 照 ToukaDev 流程自主做完任務時，這個行為會讓靈魂替人做決定。

## 決定

1. **逾時或什麼都沒選算沒回答**：全部空白才算（`[["A"], []]` 算有回答，複選題可以合法不選）。
2. **這一輪直接結束，不再呼叫模型**：`ask_user` 在 ctx 記下還沒答的問題；迴圈收完這一輪全部工具結果之後，寫一段固定文字就結束。不靠模型自己守規矩，也省一次費用。用 ctx 欄位當訊號，不比對工具回傳文字（執行器會加時間尾綴與 hook 輸出），模型的參數也碰不到 ctx。
3. **走正常完成的路**：比照沒有工具呼叫時的結束，不用使用者按停的路（`UiGenerationStopped` 後端不存檔）；工具輪上限那條路會再呼叫一次模型，也不適用。
4. **固定文字要自己夠用**：工具步驟不帶到下一輪，所以寫進問題和選項、這一輪已經回答的題目、用過的工具名稱，以及一句給模型看的「回答前不得代為決定」。題目格式不完整也要能組出文字，停下不能失敗。
5. **同一輪其他工具照常跑完**：迴圈本來就等全部工具結束。
6. **群聊也一起停**：一位成員的問題沒等到回答，下一位成員不再呼叫模型。
7. **等待秒數**：留在模型參數（`_timeout`），實際驗證用它縮短時間；只能縮短、不能拉長，不是數字就用預設的 10 分鐘。

## 後果

- 問題沒答就離開，AI 會停在那裡，要回一句才繼續。這是刻意的取捨。
- 下一輪 AI 不記得這一輪用工具查到的細節，可能要重查、多花一點費用；已經做過的實際效果都還在。
- 心跳沒有提問工具，但家對話的脈衝讀得到這段未回答的問題，只能靠固定文字那句話提醒，不是硬擋。
- 按掉問題卡時仍要等滿 10 分鐘才停（前端沒有通知後端）。
- IDE 不顯示問題（`ask_user_request` 不在它的事件名單），改完會停下並以文字顯示；IDE 每則只送最新一句，回覆時要把問題和答案一起打。
- Claude 原生格式的外部用戶端，收尾片段帶著工具呼叫（和按停的路相同）。
- Stop hook 的最後一則訊息讀的是工具輪的文字，收不到固定文字（和按停的路相同）。

## 更正 ADR-0085

- 第 37 行寫 `resumable_stream` 只在 UI 對話端點設：實際上兩個聊天端點都設，IDE 與外部 API 也拿得到這個工具。
- 第 41 行寫重新整理後問題彈窗會重現：接回串流時沒有接上提問的回呼，問題卡不會回來，要等時間到後在對話裡回覆（候選）。

## 驗證

- `tests/unit/test_ask_user_stop.py`：逾時不再呼叫模型、同輪其他工具跑完、什麼都沒選算沒回答、部分回答照常繼續、同一輪一次答一次逾時、題目格式不完整仍停下。
- 實際驗證 `session-attention.spec.ts`：問題卡關掉、固定文字出現、假模型沒有再被呼叫、回覆後接著做。
