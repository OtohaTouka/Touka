# ADR-0303：靈魂名稱與建立權限

- 狀態：✅ 已實作。一頁計畫由維護者核准，實作計畫經兩輪審查。
- 日期：2026-11-07
- 決策者：維護者
- 相關：ADR-0142（靈魂的編輯與刪除要重新輸入密碼）、ADR-0147（靈魂與使用者 ID 不能撞名）、ADR-0239（授權閘道）、ADR-0277（建立或重新註冊靈魂時的對話標記）、ADR-0293（代理人資料夾不跟隨連結）。
- 影響範圍：`ToukaProxy/src/routers/souls.py`、`src/routers/stats.py`、`src/routers/debug.py`、`src/services/soul_service.py`、`src/services/resource_manager.py`、`src/services/agent_service.py`、`src/services/authorization_gateway.py`、`src/services/avatar_service.py`、`src/utils/soul_io.py`；`ToukaMemory/src/memory_server/services/manager.py`、`tools/core_file_ops.py`、`utils/drive_bound.py`。

## 背景

靈魂、代理人與使用者的名稱會拼成資料夾路徑，例如 `<data>/soul/<名稱>`。以前有兩個問題：

- **名稱沒有檢查就拼進去**。在 Windows 上，網路分享寫法的名稱拼上去會變成網路路徑；檢查之前的 `exists()`、`resolve()` 就會先連出去。
- **不分大小寫的檔案系統**（Windows、macOS）上，只差大小寫、Windows 的 8.3 短檔名、Unicode 正規化不同的名稱，都會指到同一個資料夾。可是系統其他地方（擁有清單、不可刪名單）是逐字比對，結果別名會被當成另一個沒人擁有的代理人。

另外，「編輯靈魂」能建立新靈魂，或把還沒標成靈魂的舊資料夾轉成靈魂；除錯身分，以及一般使用者切成自己的靈魂之後，也都能這樣做。

## 決定

1. **名稱必須是單一段**（`is_zone_segment`），檢查之後才碰檔案系統。下列地方不合規時都不拼路徑：
   - 靈魂的查詢（`soul_service`）；
   - `get_vault_path`（回 None）、`get_stats_path`（422）；
   - 頭像；
   - 靈魂三個端點；
   - 舊對話統計與同步；
   - ToukaMemory 的 legacy、soul 資料夾。ToukaMemory 在 proxy 不給路徑時，不再用原本的名稱自己拼路徑。
2. **已經有的資料夾，名稱要逐字出現在目錄列表裡**。不在列表、檔案系統卻說它存在，就是別名：
   - 查靈魂時不算靈魂；
   - 建立、編輯、刪除時回 422。
   - 判斷存在交給檔案系統，所以大小寫、短檔名、正規化都擋得到。Linux 上真的並存、只差大小寫的兩個名稱，各自逐字在列表裡，照常可用。
   - 刪除時三個儲存位置（`soul`、`legacy`、個人空間）都要查；不可刪名單（DebugAgent）不分大小寫比對。
   - 列表列不完整時不動（500）。
3. **擁有權**（`is_owner` 的非人類那條路）：
   - 逐字找不到擁有者時，只差大小寫的寫法找到的擁有者，就算這個目標的擁有者。
   - 兩種都找不到時，Owner 角色只能碰逐字已知的代理人：系統代理人、靈魂、有設定的自訂模型、註冊表的 ID。
   - 人類那條路照舊逐字比對；System 角色照舊放行。
4. **誰能用「編輯」建立或轉換靈魂**：
   - 只有重新輸入密碼的人類管理員。管理員用編輯建立或轉換時，也照建立時一樣檢查向量 collection 撞名。
   - 非人類只能編輯逐字存在、而且已標成靈魂的資料夾：
     - 除錯身分可以編輯任何這樣的靈魂；
     - Owner 角色（一般使用者切成自己的靈魂）只能編輯自己，或和自己有同一位人類擁有者的靈魂（`shares_human_owner`）。沒有擁有者的靈魂不行。
5. **路徑比對**：檔案工具解析目標之前，以及登記專案根目錄時解析之前，都先用字面比對磁碟或網路分享的開頭（`same_drive`）。和根（工作區）不同就不收。專案本來就必須在工作區裡，所以正常的專案不受影響。

## 取捨與影響

- **升級後不被認得的靈魂**：
  - 名稱不合規的既有靈魂（例如 Windows 上結尾是點）。
  - 資料夾大小寫和登記的 ID 不一致的靈魂。日誌會有一條警告，要手動改成一致。
- **除錯身分不能再用編輯建立或轉換靈魂**。`config.json` 損毀或讀不到時，那個資料夾不算已標成靈魂，所以只剩管理員能用編輯修。
- **回應碼的改變**：
  - 舊對話的統計與同步端點，對不在代理人清單裡的 ID 回 403。這也包括已刪除代理人留下的 legacy 資料夾。
  - 自訂模型的端點：Owner 角色查不存在的模型，從 404 變成 403。
- **成本**：
  - `is_toukasoul` 對存在的靈魂會多列一次靈魂根目錄。
  - `is_owner` 在沒有擁有者時要算一次已知 ID 的集合（只列名稱，不組護照）。
  - 實測數字記在 PR 說明。
- **不在這次範圍**：自訂模型 ID 的別名（`custom/`）、模型自填專案編號、`/mission` 看板。

## 驗證

`tests/unit/test_soul_name_path_security.py`、`tests/unit/test_drive_bound.py`。兩道測試防線：任何碰到哨兵網路主機的檔案系統呼叫都判失敗，寫到沙盒外的動作直接失敗。在不分大小寫的 Windows 本機用實際的大小寫別名與 8.3 短檔名測；Linux CI 測新行為。
