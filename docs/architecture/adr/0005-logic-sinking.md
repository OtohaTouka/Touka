# ADR-0005: 邏輯下沉原則 (Logic Sinking)

## 狀態
已接受 (Accepted)

## 日期
2026-04-17

## 上下文 (Context)
`ToukaProxy` (Gateway) 最初承擔了過多的實體操作邏輯，例如 SQLite 資料庫的 CRUD 與檔案系統的全文檢索。這違反了 SOLID 原則中的「單一職責 (SRP)」，導致 Proxy 層過於肥大。

## 決策 (Decision)
實施「邏輯下沉原則」。將所有與特定領域（如記憶、檔案、專案）相關的複雜實作邏輯移入專門的子專案（如 `ToukaMemory`）。Proxy 僅保留「薄橋接器 (Bridge)」角色，負責權限核驗與請求轉發。

## 後果 (Consequences)
- **優點**：
  - **核心層簡潔**：Proxy 的啟動與路由邏輯變得更純粹。
  - **專業維護**：記憶與檔案引擎的優化可以在子專案中獨立進行。
  - **Schema SSOT**：工具的參數定義隨實作下沉，消除了 Proxy 端的影子定義。
- **缺點**：
  - 跨模組調試時需要追蹤更深的代碼層級。
